Where the idea came from

Ollama and Lemonade did it first.
Hemera wanted more room.

Being honest about it: the concept is not new. Two servers shaped it, and hemera keeps what they got right. What it changes is who chooses the binaries — and how many you may keep.

Inspiration

Ollama

Made a local model one command away, and its API became the one every tool speaks.

  • Kept: the Ollama API, so ollama list / run / ps / stop work unchanged
  • Kept: models load on the first request and unload when idle
  • Kept: it reads ollama's own model store directly
Inspiration

Lemonade Server

Showed that one local OpenAI-compatible server can sit in front of several engines and pick the right one for the hardware — NPU included.

  • Kept: several engines behind one server
  • Kept: more than text — images and speech too
  • Kept: AMD hardware treated as first class, NPU included
Hemera adds

Flexibility, all the way down

Both choose the engine build for you. Hemera lets you choose — and keep more than one.

  • Any release of llama.cpp, side by side, pinned per model
  • Many binaries: sd.cpp, whisper.cpp, audio.cpp, ds4, ollama's fork, your own
  • Backend per model — ROCm, Vulkan, CUDA, CPU, NPU on one machine
  • A bridge to ComfyUI for models that exist only as workflows
  • Its own 3D API, where OpenAI defines none
  • Anthropic's API too, and remote providers as local names
Why bother? llama.cpp moves fast — on 2026-08-04 alone it shipped b10253, b10254 and b10255, each in a dozen platform variants. New architectures land almost immediately, but a build that ran your model perfectly yesterday can regress today, and a server that pins one bundled binary leaves you waiting for its next release either way. Hemera keeps every build you installed, so a regression costs one click, not a week.
What it serves

Not only text.

Chat models sit next to image, video, 3D and speech models in the same list. Each one says what it makes and which endpoint to call.

Text

Chat, tool calls, reasoning, vision input and embeddings, in three dialects.

Image

Generate, and edit with several reference images — transparent backgrounds included.

Video

Text or a first frame to a clip, as a job with real progress and cancel.

3D

A picture to a .glb mesh, with vertex colours or full PBR textures.

Speech

Text to speech in a library of voices, streamed, and live voice changing.

Listening

Transcription, translation, live dictation, and who said what.

Versions & backends

Update without fear.
Roll back in one click.

Engine releases install side by side. Updating never removes what worked — and every model chooses its own build and backend.

  • A release browser built in, filtered to the variants you use, with the full rollback history.
  • Pin a model to the build that runs it best, or let it follow the latest.
  • One file, many models. A single GGUF becomes several names, each with its own context, offload, template and engine.
  • No silent CPU fallback. Hemera finds the GPU libraries each build needs and tells you when one is missing.

Built for one shared machine

Many models, one GPU,
no drama.

Everything runs on the hardware you already have. Hemera decides what loads, what waits and what gets out of the way.

Three dialects, one port

Ollama, OpenAI and Anthropic APIs, with streaming, tool calls and reasoning translated across all three — which is what lets Claude Code drive a local model.

Models say what they are

Every model lists its kind, its endpoint and its settings with ranges — enough for an app to build a form without knowing the model in advance.

Memory that is shared

Before anything loads, hemera estimates what it needs and unloads the longest-idle models — then ComfyUI's cache — only when memory is actually short.

Live audio goes first

Speech on the GPU briefly pauses the language models so it never stutters; speech on the NPU pauses nothing. Bulk jobs wait while a call is live.

Cancel actually frees the GPU

Stop an image, a video or a 3D job and the work stops — not just the wait. Hung jobs are noticed, restarted and retried once.

Remote models look local

DeepSeek, OpenAI, Gemini and Claude can sit in the same list as ordinary model names, translated into whichever dialect the client speaks.

The ComfyUI bridge

Workflows in.
Model names out.

The newest 3D and video models ship as ComfyUI workflows long before anything else runs them. Hemera does not replace ComfyUI — it fronts it, so those models become ordinary names in the same list.

Point at it

Tell hemera where ComfyUI is. Nothing is installed into it and none of its files are touched.

Hemera looks

It asks ComfyUI which model files and nodes it has. A new file of a family it knows is offered within half a minute.

Recipes match

A recipe — the workflow, and which input is the prompt, seed, size or image — turns a family of files into a model. Hemera brings its own, and makes more from the workflow templates ComfyUI ships.

Requests run

An OpenAI-shaped request fills the workflow and returns the image, the mp4 or the .glb — with progress and cancel.

Set up the bridge and its recipes →
Each family needs a recipe. A model file alone does not tell hemera how to run it: ComfyUI runs whole workflows, and which nodes a file needs lives in workflows, not in the file. So hemera offers a ComfyUI model only when a recipe covers its family. The built-in recipes cover the eight families above, and ComfyUI's own workflow templates cover many more — on ComfyUI 0.42, 163 of its 254 local templates convert into recipes. Templates that take several images, video or audio, or that make audio, are left out. Any other model needs one recipe, made once from a workflow that runs it in ComfyUI. Files no recipe recognises are listed in the web UI, never offered by guesswork.
hemera's own endpoint

A 3D API
OpenAI never wrote.

The OpenAI specification has images, video and audio — but no 3D. So hemera defines one: a picture in, a .glb mesh out. It works exactly like the Videos API, so the same client code drives both.

  • Vertex colours in minutes, or full PBR textures — base colour, metallic, roughness, normal, occlusion.
  • Real progress and cancel, and the settings actually used come back with the mesh.
  • Opens anywhere. Any glTF viewer loads the result directly — aether.ing shows it with lighting, maps and wireframe.
